# Critic 协作标记全览

Critic Markup 用 `{ ... }` 包裹的标记表示对文档的修订意见，适合审阅与协作场景。语法语义参考 [PyMdown Extensions · Critic](https://facelessuser.github.io/pymdown-extensions/extensions/critic/)，m2h 以"预览"方式实时渲染全部标记效果。

## 行内标记（五种）

| 写法 | 含义 | 渲染效果 |
| --- | --- | --- |
| `{==文字==}` | 高亮待确认 | {==高亮示例==} |
| `{>>文字<<}` | 评注 | {>>这里是评注意见<<} |
| `{--文字--}` | 建议删除 | {--删除示例--} |
| `{++文字++}` | 建议新增 | {++新增示例++} |
| `{~~旧~>新~~}` | 替换（删除线 + 下划线） | {~~旧文本~>新文本~~} |

组合用法——高亮后紧跟评注是官方推荐的搭配：这段话里 {==待确认的结论==}{>>建议补充数据来源<<} 需要复核。

## 行内行为边界

- **嵌套格式不生效**：行内内容按纯文本转义，`{++**星号原样**++}` → {++**星号原样**++}。需要内部格式时改用下面的块级标记。
- **必须同行闭合**：`{--从这里开始`（闭合标记在下一行）保持原样不解析。
- **替换缺少分隔符退化**：`{~~没有波浪箭头~~}` 按 {~~没有波浪箭头~~} 的删除样式渲染，字节不丢失。
- **与 Keys/Mark 扩展不冲突**：`++ctrl+c++` 与 `==高亮==` 照常工作，Critic 优先成对消费自己的花括号。

## 块级标记（三种）

把 `{==`、`{++` 或 `{--` 单独写在一行开启，再用 `==}`、`++}` 或 `--}` 结束，即可标注整段内容；段内仍按正常 Markdown 解析，因此**支持**完整格式。

### 高亮块

{==

这是一整段需要审阅的内容，内部支持完整 Markdown：

- 列表项一
- **加粗的**列表项二

```go
fmt.Println("块内代码同样渲染")
```

==}

### 新增块

{++

新增的整段说明，支持 [链接](https://example.com)、`行内代码` 与 ==扩展高亮==。

++}

### 删除块

{--

废弃的整段内容，可以整块删除。

--}

评注与替换没有块级形式，只能行内使用。

## 审阅场景综合示例

> 原稿：本方案 {--采用轮询实现--}{++改为事件驱动++}，轮询间隔 {~~30 秒~>实时推送~~}。{==吞吐数据待压测确认==}{>>压测报告预计下周一出<<}

## 渲染类名速查

m2h 输出以下 CSS 类，主题按其着色：

| 标记 | 输出 | 类名 |
| --- | --- | --- |
| 行内高亮 | `<mark>` | `m2h-critic` |
| 行内评注 | `<span>` | `m2h-critic m2h-critic-comment` |
| 行内删除 | `<del>` | `m2h-critic m2h-critic-delete` |
| 行内新增 | `<ins>` | `m2h-critic m2h-critic-insert` |
| 替换 | `<del>` + `<ins>` | 同上两条 |
| 块级 | `<div>` | `m2h-critic-block` + `m2h-critic-block-{highlight,insert,delete}` |

## 与 PyMdown 的差异

- m2h 仅渲染预览效果（view 模式），不提供 accept / reject 的机器处理输出。
- 行内标记内容不解析嵌套 Markdown（原样转义），块级标记内部完整解析；PyMdown 行内会渲染部分嵌套格式。
- 类名体系为 `m2h-critic*`，不使用 PyMdown 的 `critic` / `break` / `block` 类。
