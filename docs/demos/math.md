# 数学公式

m2h 在共享 Markdown 解析阶段识别数学公式，保留公式原文，再由 KaTeX
完成排版。WebUI、HTML 导出和 `m2h check` 使用相同的数学区域边界。

WebUI 默认按需加载内嵌 KaTeX；启动时加 `--cdn` 可让脚本、样式与字体从固定版本的
jsDelivr CDN 加载。HTML 导出按需使用同版本 CDN，公式语法与排版规则保持一致。

## 行内公式

使用同一行内成对的 `$...$`，例如 $dp[i][j] = a_b + c_d$。
公式里的方括号、星号、下划线与反斜杠不会被当作 Markdown 链接、强调或转义。

单 `$` 的开始标记后不能紧接空白，结束标记前不能是空白、后不能紧接数字。
因此金额 $9 和 $200 保持普通文本。未配对的行内标记按普通 Markdown 处理；
行内代码和代码围栏中的公式写法保持代码。公式内的 `\$` 原样交给 KaTeX。

## 行间公式

使用各自独占一行的 `$$`，例如：

$$
dp[r][c]
=
grid[r][c]+
\min(dp[r-1][c],dp[r][c-1])
$$

也支持同一行内的 `$$x = y$$`。多行公式可位于列表或引用块内，容器前缀
不会成为公式内容。独占一行的开始标记开启原文块，直到独占一行的结束标记；
缺少结束标记时原文块延续至容器或文档末尾，不自动补齐结束标记，也不验证 TeX 语法。
请始终配对书写分隔符。

独立的 `=` 不会生成一级标题，`dp[r][c]` 不会触发 `reference.undefined`，
公式也不会出现在文档目录中。公式内的 `<`、`>`、`&` 会进行 HTML 转义，
浏览器读取的公式文本保持原样，不执行其中看似 HTML 的标签。

## 边界

- 推荐使用美元分隔符；`\(...\)` 与 `\[...\]` 仍会受到 Markdown
  反斜杠转义影响，不属于本次支持的解析分隔符。
- GFM 表格首先按列分割，再解析单元格。单元格内的竖线必须转义，
  包括代码片段与公式中的竖线；代码片段里的裸 `||` 仍会触发
  [`table.column-mismatch`](checkers/10-table-column-mismatch.md)。
- 普通正文中的 Setext 标题、引用链接、HTML 与表格保持原有规则；
  公式区域之外的真实错误仍由检查器报告。
