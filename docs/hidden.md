# 隐藏文件发布

m2h 对目录输入默认隐藏点前缀路径，把"文件发现"与"文件访问"统一到同一个发布范围里：侧边栏、文档路由、原始内容、静态资源、全文搜索与 `m2h check` 看到的是同一份可见文件集合。需要发布隐藏内容时用 `--hidden` 显式开启，本文档记录完整的发布规则与保护边界。

## 功能范围

- **默认隐藏**。`m2h ./docs` 与 `m2h check ./docs` 都不发现、不发布、不检查点前缀路径；`--hidden` 开启，`--no-hidden` 显式恢复默认（与 `--gitignore` 相同的反向布尔形式）。
- **开启即全入口同步**。`--hidden` 后隐藏文档与资源同时进入侧边栏、`/api/document`、`/raw/`、`/assets/` 与 `/api/search`，`check` 同时检查它们，两端看到同一份范围。
- **单文件输入不受影响**。用户在命令行显式指定一个 Markdown 文件，即是明确的发布动作——`m2h .draft.md` 与 `m2h check .draft.md` 无论开关如何都照常工作。
- **多根输入各自独立**。`m2h docs wiki` 中每个目录根应用同一个 `--hidden` 配置，互不影响。
- **`--hidden` 只放宽隐藏路径过滤**。它不覆盖 `.gitignore`、`--glob`、`--depth`、符号链接与根目录隔离等其余限制；一个被 `.gitignore` 排除的隐藏文档需要同时 `--hidden --no-gitignore` 才能纳入范围。

生效的访问入口（拒绝时对访客一律表现为 404）：

| 入口 | 默认 | `--hidden` |
| --- | --- | --- |
| `/api/files` 侧边栏 | 不含隐藏文档 | 含普通隐藏文档 |
| `/api/document`、`/raw/`、`/doc/` | 隐藏文档 404 | 普通隐藏文档 200 |
| `/assets/` | 隐藏资源 404 | 普通隐藏资源 200 |
| `/api/search` | 不索引隐藏文档 | 索引普通隐藏文档 |
| `m2h check` | 不检查隐藏文档，引用报告 not-served | 同时检查，引用正常解析 |

## 永久保护路径

隐藏发布是一个用户可配置的发现规则，保护边界不是。以下路径在任何层级都不可发布，`--hidden` 也无法解除：

| 路径形态 | 示例 |
| --- | --- |
| `.git` | `.git/config`、worktree 的 `.git` 指针文件 |
| `.ssh` | `.ssh/id_ed25519`、`home/.ssh/known_hosts` |
| `.env` 及 `.env.*` | `.env`、`.env.local`、`.env.production` |

保护在发现遍历时优先生效：目录不进入子树，文件不进入结果；对符号链接同样在请求路径与解析后的规范路径上各判定一次，可见别名（`config.txt → .env.production`）无法绕过。`.gitignore`、`.github/`、`.notes/` 等普通点前缀路径不受保护，属于 `--hidden` 的正常范围。

## 判定与链接一致性

- **符号链接双重判定**。先按请求路径（别名）判定，再做文件系统解析后按规范目标判定：默认运行中可见别名指向隐藏文档时不发布（避免标题泄漏），`--hidden` 下两者都可发布；保护路径两种形态下都拒绝。
- **check 与 Web 同一范围**。`check` 复用与 serve 相同的文件发现与访问判定：引用被排除的隐藏 Markdown 时报告 `markdown-target.not-served` 并注明隐藏原因，隐藏图片等资源目标报告 `local-target.missing`；开启 `--hidden` 后这些诊断消失。`check` 报告有效的链接，浏览器一定不会收到 404。
- **单文件作用域的邻域保持默认**。单文件输入没有自己的 `--hidden` 决策，其隐藏邻域资源保持 404，显式输入的范围不随开关静默扩大。

上述矩阵（普通隐藏、保护路径、别名、单文件输入、链接一致性）在 `internal/files`、`internal/check`、`internal/server` 的单元测试与 `web/e2e/hidden.spec.ts` 浏览器回归中固化。
